# grayroll-02 拍板说明：爬坡单步比例增量封顶（甲路径封死）

- 需求编号：grayroll-02
- 领域：应用开发 · 全栈开发
- 当班封板日期：2026-11-26
- 事故现场：`search.vector_recall`（flag 2）预发爬坡计划 `10% -> 50%`，一次 apply-next 单步跳变 40 个百分点，正式规则被整笔改写，求值页命中面骤扩、对比页漂移灯灭。

## 一、正式规则（封死，禁止第三路折中）

1. 爬坡推进接口 `POST /api/schedules/{id}/apply-next` 每次推进的比例增量
   （本步目标比例 − 当前正式规则比例）**不得超过 20 个百分点**。
2. **甲路径（本班次唯一取舍，已封死）**：检测到超步即**整笔拒写**：
   - HTTP 400，错误明细 `单步爬坡增量不得超过20个百分点`；
   - 正式规则册 `flag_rules` 零增零改（不删旧行、不插新行、不升版本）；
   - 发布账 `releases` 零增；
   - 爬坡计划 `rollout_schedules.cursor_step/status` 不动；
   - 不写变更历史、不写审计。
3. **乙路径（影子爬坡草案）本次封存不用**：禁止把超步数据落任何爬坡影子表，
   禁止“先影子后拆步升正”的折中链路。偏离本取舍即记偏航并拒写。
4. 边界口径：增量恰好 20 个百分点为合法；`>` 20 才拒写。
   首次爬坡（该开关/环境无正式规则）无基线可比，按合法首步处理。
5. 合法步进仍贯彻甲路径同事务语义：同事务写正式 `flag_rules`（版本 +1）、
   写 `releases` 发布账（同版本号）、推进游标，三者同成同败；
   求值页比例与发布版本必须跨表同源可联查。

## 二、并发口径

- 两路会话同时抢修同一开关+环境的爬坡，必须争抢同一把爬坡锁
  `flag-schedule:{flag_id}:{env_id}`（复用 `locks.acquire/release` 行锁）。
- 败方拿锁即失败：HTTP 409，仅在 `contention_marks` 留争用痕，
  正式规则、发布账、游标零改。禁止无锁双成。

## 四、同源口径

熔断页、求值页、覆盖页、历史页、开关页与规则/发布/爬坡数据同库同源；
合法步进后求值页返回的 `percent/version` 必须等于正式规则行，且与
`releases` 最新正式版本号一致。
